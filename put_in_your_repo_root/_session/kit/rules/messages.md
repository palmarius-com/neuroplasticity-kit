# Situation Rules: Messages and Customer Documents

Kit file, identical in every project, changed only through the kit. Read
before drafting a mail, forum or chat message and before building or
changing a document for a customer.

## Drafts

- Short blocks, one thought each, a blank line between, so a human reads
  block by block. Keep them brief.
- Once the user edits a draft it is the user's text: do not change the file
  any more. Propose wording in the chat; read the file again only when
  told.
- Credit people once, where credits live, not in every new post. Use the
  name a person goes by in public.

## Documents for Customers

- Every price or figure is recalculated from the user's numbers. Show the
  formula in two or three lines and get it confirmed BEFORE the document is
  built or changed.
- An own assumption never goes into a customer document.
- Never put what the user keeps private (margin, cost structure) into a
  customer document.

## Mail and Attachments

- An attachment handed over: check its size (0 bytes = destroyed, look for
  another copy) and copy it into the repo at once.
- Reading the user's mailbox by script is a take-over of the user's machine
  (`core.md`, Hard Rule 4).
